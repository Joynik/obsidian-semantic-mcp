# OSM: карта проекта для AI-агентов

Этот файл описывает текущую структуру и связи между компонентами. Перед правкой сверяйте детали с кодом: файл служит картой, а не заменяет исходники. Пользовательские команды и установка описаны в корневом `README.md`; обязательные правила работы — в `AGENTS.md`.

## Что делает OSM

`osm` — CLI и точка входа локального MCP-сервера для Markdown-хранилищ Obsidian. Заметки остаются файлами в хранилище. OSM читает их, разбивает на фрагменты, получает векторы через Ollama и хранит поисковый индекс в **одном** выбранном backend: PostgreSQL + pgvector или Qdrant. В Qdrant-режиме PostgreSQL не нужен. MCP-клиенты запускают `osm run` как процесс со связью через stdin/stdout. Dashboard запускается отдельно, только по команде.

| `src/server.py` | MCP-инструменты, готовность сервера, работа с файлами, Ollama, фрагменты и ссылки заметок, индексация, поиск, наблюдатели, безопасная перестройка индекса. |
| `src/postgres.py` | Операции с заметками, фрагментами, связями, поиском и состоянием индекса в PostgreSQL. |

## Путь запуска и конфигурации

1. `osm init` выбирает vault, backend, Ollama и модель, проверяет доступность служб и сохраняет параметры в `~/.config/obsidian-semantic-mcp/native_runtime.json`. Подключение каждого MCP-клиента и право записи для него запрашиваются отдельно.
2. Установленный `osm run` через `src/launcher.py` читает сохранённую конфигурацию; исходный checkout может использовать `.env`. Клиентские настройки должны содержать команду `osm run`, а не копии URL, паролей и путей к vault.
3. `src/server.py` открывает MCP-протокол на stdin/stdout. Логи и диагностика идут в stderr и `~/.local/state/obsidian-semantic-mcp/osm.log`; нельзя печатать обычные сообщения в stdout сервера.
4. Фоновый запуск ждёт, пока Ollama вернёт **реальную** размерность вектора. При недоступности повторяет запрос. Затем инициализирует выбранное хранилище, обрабатывает каждый vault отдельно и запускает наблюдателей файлов. MCP-процесс уже может принимать запросы, а состояние индексации отражается в статусе готовности.
5. `osm stop` останавливает запущенные локальные MCP-процессы; MCP-клиент может позднее запустить новый. `osm dashboard` и `osm dashboard stop` управляют отдельным процессом панели.

## Индексация и поиск

- `index_vault()` обходит `.md` файлы. Скрытые и системные папки исключаются; папки `archive` по умолчанию тоже. Их включение задаётся через `osm init` или `OBSIDIAN_INDEX_ARCHIVE=yes` для checkout.
- `split_note()` создаёт перекрывающиеся фрагменты. Для индексации вызывается `embedding_input(..., "document", model)`, для смыслового запроса — `embedding_input(..., "query", model)`. Профиль Qwen3 и профиль Nomic отличаются; не заменяйте их общим префиксом.
- Хеш содержимого позволяет пропускать неизменённые заметки. Файловый наблюдатель обновляет или удаляет записи индекса после изменений. На сетевых томах возможен polling; ручной выбор — `VAULT_WATCH_POLLING`.
- Wikilink с путём разрешается по пути относительно vault. Короткая ссылка разрешается только при единственном совпадении среди настроенных vault; неоднозначную связь нельзя записывать произвольно.
- Поиск имеет semantic, keyword и hybrid режимы. PostgreSQL использует настраиваемый язык полнотекстового поиска; Qdrant использует собственный BM25. Смысловой и гибридный поиск работают с фрагментами и могут показать соседние фрагменты найденной заметки.
- Изменение модели делайте через `osm migrate`, а полную перестройку — через Safe Rebuild. Новый индекс готовится отдельно и становится активным после проверки. Нельзя смешивать векторы разных моделей или удалять текущий индекс до успешного переключения.

## Инварианты при изменениях

- Не изменяйте и не удаляйте файлы заметок, существующие данные БД и архивы индекса ради рефакторинга. Операции очистки должны касаться только подтверждённых отсутствующих файлов.
- Установленная команда не должна зависеть от checkout. При изменении ресурсов проверьте включение их в wheel и запуск `osm` вне каталога проекта.
- Настройки конкретной машины и изменяемые URL/пути не закрепляйте в коде. Не записывайте секреты в клиентские конфиги, stdout, логи или этот документ.
- Для новой возможности проверяйте оба backend, обычную индексацию, Safe Rebuild, миграцию модели и наблюдатель файлов там, где поведение затрагивает индекс.
- Не меняйте настройки MCP-клиентов без явного согласия пользователя. Право записи у каждого клиента отдельное; по умолчанию оно выключено.
- Сохраняйте поддержку macOS, Windows и Linux в платформенных ветках. Проект не использует Docker.
- Не делайте commit или push без запроса владельца. Правила изменения версии находятся в корневом `AGENTS.md`.

## Быстрая проверка после правок

```sh
uv run ruff check osm_cli.py src
uv run ruff format --check osm_cli.py src
uv run ty check osm_cli.py src
git diff --check
```

Проверки с живым PostgreSQL, Qdrant, Ollama или реальным vault отмечайте отдельно от статического анализа. Не утверждайте, что интеграция проверена, если запускались только Ruff и ty. Тесты и существующие данные не меняйте без соответствующего запроса.
